I am a software engineer. I work on the frontend and the backend, including systems that use a language model in the workflow. **4+ years.** On the frontend I build the screens people use. On the backend I design the API and split the work across services where the load requires it. I run the orchestration around them, containers, pipelines, and the infrastructure they sit on, and I automate the tests. A client gets one person who can build both sides, prove the system, and operate it.

| | |
|---|---|
| **Bayan** | Municipal payments in Somalia for **more than 400,000 people**. Collection, admin and collector dashboards, and the REST API those desks use. |
| **AEC Tenderlink** | SaaS for tendering, in production at [aectenderlink.com](https://www.aectenderlink.com). Firms publish and answer tenders. Next.js and a Node API. |
| **Mavuno Guard** | SaaS for farm risk. Weather, trees, and field operations, so a manager sees the risk before it becomes a loss. |
| **Provenance** | AI for asylum and refugee work. A language model helps researchers gather country-of-origin reporting. The person still decides the case. |
| **HR** | Recruitment, departments, attendance, events, and the dashboard. Merged into [Ivy Community HR](https://github.com/ivycommunity/hr/pull/1). |
| **QA automation** | [Playwright API framework](https://github.com/nahorfelix/api-automation-framework-js). The suite calls the REST contract the way a client does. A break fails the build. |

That is the work I take on: the frontend and the backend for a real operator, an AI step where the product needs one, automated checks on the API, and the DevOps around the release. Docker, Kubernetes, GitHub Actions, and Terraform are the orchestration I have used to ship and keep these systems running. ISP provisioning, SACCO risk, and multi-tenant logistics are the same practice at a different scale.
